# 1부. 비트와 정수 표현

양자화를 이해하려면 먼저 **비트열 자체**와 그 비트열을 **숫자로 해석하는 규칙**을 구분해야 한다. 4비트 양자화에서 말하는 `4비트`는 우선 0과 1 네 자리로 만들 수 있는 16개 상태를 뜻한다. 그 16개 상태에 어떤 숫자를 대응시킬지는 자료형과 양자화 방식이 결정한다.

## 학습 목표

이 장을 마치면 다음 내용을 설명할 수 있다.

- 비트와 바이트가 무엇인지 설명한다.
- `n`비트가 `2^n`개 상태를 만든다는 뜻을 이해한다.
- 같은 비트열을 unsigned와 signed 정수로 다르게 해석할 수 있음을 설명한다.
- 2의 보수로 음수를 인코딩하고 다시 해석한다.
- signed INT4의 범위가 `-8~7`인 이유를 설명한다.

## 1. 비트는 두 가지 상태를 가진다

비트(bit)는 `0` 또는 `1` 중 하나의 값을 가진다. 비트가 하나라면 가능한 상태는 두 개다.

```text
0
1
```

비트가 두 개라면 각 자리마다 두 가지 선택이 있으므로 상태는 네 개가 된다.

```text
00
01
10
11
```

일반적으로 `n`비트로 만들 수 있는 서로 다른 비트열은 다음과 같다.

```text
2 × 2 × ... × 2 = 2^n
```

따라서 4비트는 `2^4 = 16`개 상태를 표현한다. 8비트는 `2^8 = 256`개 상태를 표현하며, 8비트를 한 바이트(byte)라고 부른다.

중요한 점은 **상태 수와 숫자의 의미가 아직 같은 말이 아니라는 것**이다. `1101`이라는 비트열이 어떤 숫자인지는 그것을 unsigned로 볼지, signed로 볼지에 따라 달라진다.

## 2. 이진수의 자리값

십진수 `352`는 각 자리의 숫자에 10의 거듭제곱을 곱해 해석한다.

```text
352 = 3×10² + 5×10¹ + 2×10⁰
```

이진수도 같은 원리지만 밑이 2다. 오른쪽부터 자리값이 `1, 2, 4, 8, ...`로 증가한다.

```text
1101₂ = 1×2³ + 1×2² + 0×2¹ + 1×2⁰
       = 8 + 4 + 0 + 1
       = 13
```

이 계산은 `1101`을 **부호 없는 정수**로 해석한 결과다.

## 3. 4비트의 모든 상태

4비트 비트열을 작은 코드부터 차례로 나열하면 다음과 같다.

| 비트열 | unsigned 해석 | 2의 보수 signed 해석 |
|---|---:|---:|
| `0000` | 0 | 0 |
| `0001` | 1 | 1 |
| `0010` | 2 | 2 |
| `0011` | 3 | 3 |
| `0100` | 4 | 4 |
| `0101` | 5 | 5 |
| `0110` | 6 | 6 |
| `0111` | 7 | 7 |
| `1000` | 8 | -8 |
| `1001` | 9 | -7 |
| `1010` | 10 | -6 |
| `1011` | 11 | -5 |
| `1100` | 12 | -4 |
| `1101` | 13 | -3 |
| `1110` | 14 | -2 |
| `1111` | 15 | -1 |

비트열은 똑같지만 해석 규칙이 다르다.

```text
1101 -> unsigned에서는 13
1101 -> signed INT4에서는 -3
```

비트 자체에 양수나 음수라는 의미가 붙어 있는 것이 아니다. 자료형이 비트열을 읽는 규칙을 정한다.

## 4. unsigned 정수

unsigned 정수는 모든 비트를 크기를 나타내는 데 사용한다. `n`비트 unsigned 정수의 범위는 다음과 같다.

```text
0 ~ 2^n - 1
```

4비트라면 다음 범위가 된다.

```text
0 ~ 2^4 - 1 = 0 ~ 15
```

각 비트를 `b₃ b₂ b₁ b₀`라고 하면 4비트 unsigned 값은 다음처럼 계산한다.

```text
b₃×2³ + b₂×2² + b₁×2¹ + b₀×2⁰
```

예를 들어 `1010`은 `8 + 2 = 10`이다.

## 5. signed 정수와 2의 보수

signed 정수는 양수와 음수를 모두 표현해야 한다. 현대 컴퓨터의 고정 폭 정수는 일반적으로 **2의 보수(two's complement)** 방식으로 음수를 표현한다.

`n`비트 2의 보수 정수의 범위는 다음과 같다.

```text
-2^(n-1) ~ 2^(n-1) - 1
```

4비트 signed 정수라면 다음과 같다.

```text
-2³ ~ 2³ - 1
-8 ~ 7
```

양수 쪽은 `0~7`까지인데 음수 쪽은 `-8~-1`까지라서 한 칸 비대칭이다. 비트열 `0000` 하나를 0이 사용하고, 남은 15개 상태를 양수 7개와 음수 8개가 나누기 때문이다.

### 5.1 최상위 비트의 자리값

2의 보수는 최상위 비트의 자리값을 음수로 보면 빠르게 해석할 수 있다. 4비트 `b₃ b₂ b₁ b₀`의 signed 값은 다음과 같다.

```text
-b₃×2³ + b₂×2² + b₁×2¹ + b₀×2⁰
```

`1101`을 이 식으로 계산하면 다음과 같다.

```text
-1×8 + 1×4 + 0×2 + 1×1 = -3
```

같은 비트열을 unsigned로 계산했을 때의 13과 전혀 다른 값이다.

### 5.2 음수를 만드는 방법: 비트 반전 후 1 더하기

양수 `3`을 4비트로 쓰면 `0011`이다. `-3`의 2의 보수를 만들 때는 비트를 모두 뒤집고 1을 더한다.

```text
  0011   (+3)
  1100   (비트 반전)
+ 0001
------
  1101   (-3)
```

다시 `1101`의 비트를 뒤집고 1을 더하면 `0011`이 되므로 크기 3을 확인할 수 있다.

가장 작은 4비트 signed 값 `-8`은 `1000`이다. 반대로 `+8`은 4비트 signed 범위를 벗어나므로 표현할 수 없다.

## 6. 고정 비트 폭과 오버플로

고정 폭 정수에서는 계산 결과도 정해진 비트 수 안에 들어가야 한다. 4비트 signed 정수에서 가장 큰 값은 `0111`, 즉 7이다. 여기에 1을 더하면 수학적으로는 8이지만, 4비트 결과만 남기면 `1000`이 된다.

```text
  0111   (7)
+ 0001   (1)
------
  1000   (signed 해석: -8)
```

이 현상을 오버플로(overflow)라고 한다. 비트열 덧셈이 틀린 것이 아니라, 수학적 결과 8을 4비트 signed 범위가 담지 못한 것이다.

양자화 코드를 다룰 때도 범위를 벗어난 값을 어떻게 처리할지 정해야 한다. 뒤의 장에서는 범위 밖 값을 최솟값이나 최댓값으로 제한하는 **클리핑(clipping)**을 다룬다.

## 7. Python에서 고정 폭 정수를 다룰 때의 주의점

Python의 기본 `int`는 필요에 따라 자릿수가 늘어나는 임의 정밀도 정수다. 따라서 Python에서 `7 + 1`은 자연스럽게 8이 되며, 자동으로 4비트 오버플로가 발생하지 않는다.

고정 폭 동작을 실험하려면 다음 요소를 직접 지정해야 한다.

- 몇 비트를 사용할지
- 값의 허용 범위가 어디까지인지
- 비트열을 unsigned로 읽을지, 2의 보수 signed로 읽을지

이 저장소의 [`src/bits_and_integers.py`](../src/bits_and_integers.py)는 이 규칙을 코드로 분리해 보여준다.

```python
from src.bits_and_integers import (
    decode_twos_complement,
    decode_unsigned,
    encode_twos_complement,
)

bits = "1101"

print(decode_unsigned(bits))          # 13
print(decode_twos_complement(bits))   # -3
print(encode_twos_complement(-3, 4))  # 1101
```

## 9. INT4 양자화로 이어지는 연결점

4비트 양자화에서 가장 먼저 확보되는 것은 16개의 코드다. 다만 실제 양자화 방식이 이 코드들을 사용하는 방법은 서로 다를 수 있다.

- unsigned INT4는 보통 `0~15` 코드로 해석할 수 있다.
- 2의 보수 signed INT4는 `-8~7`로 해석할 수 있다.
- 대칭형 양자화는 0을 중심으로 양수와 음수 범위를 맞추기 위해 `-7~7`만 사용하고 `-8`을 비워 두기도 한다.
- 실제 저장에서는 4비트 코드 두 개를 한 바이트에 묶을 수 있다. 교육용 NumPy 코드가 `int8` 배열을 사용한다면 값의 범위만 INT4일 뿐, 아직 두 코드를 한 바이트에 패킹한 것은 아니다.

따라서 `4비트 양자화`라는 표현만 보고 곧바로 저장 형식이나 숫자 범위를 하나로 단정하면 안 된다. 뒤의 장에서는 **코드**, **스케일**, **실제 저장 형식**을 분리해서 다룬다.
